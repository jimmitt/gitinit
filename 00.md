Git gets much easier when you stop treating it as a remote file server. It is a
tool for building and exchanging a history of **commits**.

A commit is a saved snapshot of your project plus a message, an author, a time,
and a link to its parent commit. That chain of snapshots is the project's
history. Every commit has an identifier, such as `a1b2c3d`, calculated from its
contents and history.

## Your repository is local

When you clone a project, Git gives you the files you can edit *and* the
repository's history. Most everyday commands work locally. You can inspect old
work, create a branch, and commit on an airplane.

This leads to Git's most useful separation:

- `git commit` records work in your local repository.
- `git push` publishes commits to another repository.

Committing does not surprise your teammates. Push only after your commits say
what you want them to say and the project checks pass.

## Three places, not one

Git asks you to picture your work in three places:

1. The **working tree** contains the files you are editing.
2. The **staging area** (also called the index) is the proposed contents of your
   next commit.
3. The **repository** stores commits you have already made.

`git add` copies selected changes from the working tree into the staging area.
`git commit` turns the staged snapshot into a commit. This extra step is useful:
you can edit three files, stage two that belong together, and commit a focused
change without hiding or deleting the third.

```text
working tree  -- git add -->  staging area  -- git commit -->  repository
```

## Branches are movable names

A branch is a lightweight name pointing to one commit. When you commit, the
current branch moves forward to the new commit. Creating a branch does not copy
the project; it creates another name for the current point in history.

`HEAD` is Git's name for where you currently are—normally the branch you have
checked out. If `HEAD` points to `main`, new commits advance `main`. If you
switch to `feature/login`, new commits advance that branch instead.

## Remotes are other repositories

A remote is a named connection to another Git repository. The conventional name
for the repository you cloned is `origin`, but that name is not magical. You can
have several remotes.

Git records its latest knowledge of remote branches with names such as
`origin/main`. `git fetch origin` updates those remote-tracking names without
changing your working files. You decide when and how to integrate that work.

## A compact vocabulary

- **clone**: make a local repository from an existing one
- **commit**: record a staged snapshot locally
- **branch**: a movable name for a line of work
- **fetch**: download objects and update remote-tracking branches
- **merge**: combine histories
- **pull**: fetch, then integrate into the current branch
- **push**: send commits and update a branch in another repository

These ideas explain almost everything in the chapters ahead. You do not need to
memorize Git all at once. Start with the daily loop: inspect, stage, review,
commit, synchronize.
